## 🎯 What's New in v4.2.2

### **1. Liquidity Rejection (instead of scaling)**
- **Problem**: Bot was scaling positions down to $2-5 on low liquidity, causing poor execution and high slippage
- **Solution**: Now **REJECTS** trades if:
  - Liquidity factor < 0.4
  - Adjusted position size < $5
- **New ENV params**:
  ```env
  MIN_LIQ_FACTOR=0.4
  MIN_ADJUSTED_USD=5.0
  ```

### **2. Fresh Impulse Pump Detection**
- **Problem**: Bot was catching pumps that already extended
- **Solution**: Requires **fresh volume spike** in last 15m candle:
  - Current 15m volume must be >= 2x previous 15m volume
  - Rejects if already pumped > 12% in SIDEWAYS regime
- **New ENV params**:
  ```env
  PUMP_SPIKE_MULT=2.0
  PUMP_SPIKE_LOOKBACK=1
  PUMP_MAX_24H_EXTENDED=12.0
  ```

### **3. CORE Rejection Observability**
- **Problem**: No visibility into why trades were rejected by risk engine
- **Solution**: Structured `[CORE_REJECT]` logging for **all 7 rejection types**:
  1. DAILY_LOSS_HARD
  2. COOLDOWN
  3. DAILY_LOSS_LIMIT
  4. CORRELATION_LIMIT
  5. MAX_POSITIONS
  6. MAX_PUMP_POSITIONS
  7. PORTFOLIO_HEAT
- **Benefit**: Auto-optimizer can now analyze both pre-entry (PUMP_DEBUG) and post-entry (CORE_REJECT) rejections

## ✅ Expected Results

### **Before v4.2.2:**
- Low-liquidity trades scaled to $2-$5 → Poor execution, high slippage
- Catching extended pumps → Late entries, low win rate
- No visibility into CORE rejections → Can't optimize

### **After v4.2.2:**
- Low-liquidity trades **rejected** → Better trade quality
- Only fresh volume impulses → Early entries on new pumps
- Full rejection observability → Optimizer can tune end-to-end pipeline

## 🔗 Integration with Auto-Optimizer

The auto-optimizer (`tools/auto_env_optimizer.py`) now has **complete visibility**:

**Pre-entry rejections** (PUMP_DEBUG):
- VOLUME_TOO_LOW
- SCORE_TOO_LOW
- MOMENTUM_TOO_LOW
- RETURN_OUT_OF_RANGE
- etc.

**Post-entry rejections** (CORE_REJECT):
- COOLDOWN
- PORTFOLIO_HEAT
- MAX_POSITIONS
- CORRELATION_LIMIT
- etc.

This allows the optimizer to:
1. Detect if signals are being generated but rejected by CORE filters
2. Adjust signal generation params to match risk constraints
3. Provide end-to-end tuning of the entire pipeline
